## Project Overview

**Builders Connect** (`BuildersQRLabels.py`) is a Windows-only desktop application for Builders Inc., a truss manufacturing company. It manages the full job workflow:

1. **Validate** job folders for required files
2. **Generate** printable QR sticker PDFs for truss identification
3. **Upload** completed job packages to cloud storage (Dropbox or OneDrive)
4. **Sync** files between local storage and cloud

The app started as two separate programs (Sticker Manager and Cloud Manager) and is being merged into a single unified application. The two legacy apps remain in the root for reference.

## Job Folder Requirements

### Folder Naming

Job folders must match **`XXXXXX-XXX`** (6 digits, hyphen, 3 digits): `re.fullmatch(r'\d{6}-\d{3}', folder_name)`

Example: `208135-001`

### Watch Folder (Cloud upload source)

```
Watch Folder/
└── [any subfolder]/
    └── _Final Jobsite Package QR/
        ├── 208135-001.csv
        ├── 208135-001_SomeName.pdf       ← included
        └── 208135-001_JOB_anything.pdf   ← EXCLUDED
```

Exclusion pattern: `re.match(rf"{re.escape(job_id)}_JOB_", filename, flags=re.IGNORECASE)`

### Target / Jobs Folder (Sticker Manager + upload destination)

```
Target Folder/
└── 208135-001/
    ├── 208135-001.csv                       ← REQUIRED for sticker generation
    ├── 208135-001_QR.svg                    ← REQUIRED for sticker generation
    ├── Stickers_208135-001.pdf              ← GENERATED by StickerEngine
    └── 208135-001_Stickers_Summary.txt      ← GENERATED by StickerEngine
```

## CSV File Requirements

File must be named exactly `{JOBNUMBER}.csv`. Column names are case-insensitive (normalize with `.str.lower()`).

| Column | Type | Purpose |
|---|---|---|
| `jobnumber` | str | Filter rows: `df[df['jobnumber'].astype(str).str.strip() == job_id]`; stored as `"208135-001"` |
| `trsname` | str | Truss code shown large on sticker |
| `trusstype` | str | Truss type description |
| `batch` | str | Batch grouping (last 2 chars = batch code) |
| `customer` | str | Client name — truncated to 25 chars on sticker |
| `jobname` | str | Project name — truncated to 25 chars on sticker |
| `qty` | int | Number of stickers per truss |
| `ply` | int | If `> 1`: total = `qty × ply`; if `== 1`: total = `qty` |

## Sticker Layout

Each sticker page is **100mm × 30mm**. Truss code font: 48pt (≤4 chars), 42pt (5), 36pt (6), 30pt (7+).

- **Cloud QR**: links to the cloud share URL (from `{job_id}_QR.svg`)
- **Token QR**: encodes `{batch}|{truss_code}|{sticker_type}|{uuid_token}`
- **Sticker type**: `Q01/05` (QTY) or `P01/05` (PLY)

## Cloud Provider Integration

Active provider stored in `config.json` as `"cloud_provider": "dropbox"` or `"onedrive"`.

- **Dropbox**: OAuth2 via `DropboxOAuth2FlowNoRedirect`; tokens in `token_dropbox.json`; upload root `/Cloud Manager Uploads/{job_id}/`
- **OneDrive**: OAuth2 via `msal`; tokens in `token_onedrive.json`; same upload convention; requires Azure app registration

Both providers must upload files, create a shareable folder link, then generate `{job_id}_QR.svg` from that link.

## Settings (config.json)

`config.json` holds only **per-machine / bootstrap** settings. Shared path configuration lives in the database `settings` table so all machines stay in sync automatically.

```json
{
  "db_path": "\\\\SERVER\\BuildersQRLabels\\builders_qr_labels.db",
  "cloud_provider": "dropbox",
  "dropbox_app_key": "",
  "dropbox_app_secret": "",
  "onedrive_client_id": "",
  "onedrive_client_secret": "",
  "onedrive_tenant_id": "common",
  "company_name": "Builders Inc.",
  "company_address": "2644 Byington Solway Rd, Knoxville"
}
```

`watch_folder`, `target_folder`, `auto_refresh_seconds`, and the log file path are stored in the **database `settings` table** (see below), not in `config.json`.
```

## Threading Rules

Tkinter is **not thread-safe**. All UI updates from background threads MUST use `root.after(0, callback)`.

```python
# WRONG
self.tree.item(item, values=(...))

# CORRECT
self.root.after(0, lambda: self.tree.item(item, values=(...)))
```

Long operations (scanning, generating, uploading) run in `daemon=True` threads.

## Shared / Network Data (Phase 9 plan)

For multi-machine use, store a SQLite DB on a network share. `db_path` in `config.json` is the only bootstrap setting needed; all other shared config (folder paths, refresh interval, log path) lives in the DB. Fall back to a local `builders_qr_labels.db` when the network is unavailable.

**Database tables:**

- `jobs` — keyed on `job_id`; holds sticker/cloud status, `last_updated`, `updated_by`
- `settings` — key/value pairs for shared configuration:

| Key | Example Value |
|---|---|
| `watch_folder` | `\\SERVER\Jobs\Watch` |
| `target_folder` | `\\SERVER\Jobs\Target` |
| `auto_refresh_seconds` | `30` |
| `log_path` | `\\SERVER\BuildersQRLabels\builders_qr_labels.log` |
