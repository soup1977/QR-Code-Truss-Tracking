## Project Overview

**Builders Connect** is a Windows desktop application for Builders Inc., a truss
manufacturing company. It manages the full job workflow:

1. **Validate** job folders for required files
2. **Generate** printable QR sticker PDFs for truss identification
3. **Upload** completed job packages to cloud storage (Dropbox or OneDrive)
4. **Sync** files between local storage and cloud

The app started as two separate programs (Sticker Manager and Cloud Manager) and is
being merged into a single unified application.

## Job Folder Requirements

### Folder Naming

Job folders must be **exactly 7 digits**: `re.fullmatch(r'\d{7}', folder_name)`

Examples: `1234567` ✓ — `123456` ✗ — `12345678` ✗ — `ABC1234` ✗

### Watch Folder (Cloud upload source)

The Cloud Manager watches for a hardcoded subfolder named `_Final Jobsite Package QR`
anywhere inside the configured Watch folder (searched recursively via `os.walk`):

```
Watch Folder/
└── [any subfolder]/
    └── _Final Jobsite Package QR/
        ├── 1234567.csv
        ├── 1234567_SomeName.pdf       ← included
        └── 1234567_JOB_anything.pdf   ← EXCLUDED (ignored, never uploaded)
```

The `_JOB_` exclusion pattern: `re.match(rf"{re.escape(job_id)}_JOB_", filename, flags=re.IGNORECASE)`

### Target / Jobs Folder (Sticker Manager + upload destination)

```
Target Folder/
└── 1234567/
    ├── 1234567.csv                       ← REQUIRED for sticker generation
    ├── 1234567_QR.svg                    ← REQUIRED for sticker generation
    │                                       (generated by cloud upload step)
    ├── 1234567_SomeName.pdf              ← uploaded to cloud
    ├── 1234567_JOB_anything.pdf          ← IGNORED everywhere
    ├── Stickers_1234567.pdf              ← GENERATED by StickerEngine
    └── 1234567_Stickers_Summary.txt      ← GENERATED by StickerEngine
```

## CSV File Requirements

File must be named exactly `{JOBNUMBER}.csv` (e.g., `1234567.csv`).

**Required columns** (column names are case-insensitive — normalize with `.str.lower()`):

| Column | Type | Purpose |
|---|---|---|
| `jobnumber` | int | Filter rows to current job — `df[df['jobnumber'] == int(job_id)]` |
| `trsname` | str | Truss code shown large on sticker (e.g., `M001`) |
| `trusstype` | str | Truss type description |
| `batch` | str | Batch grouping (last 2 chars used as batch code for print selection) |
| `customer` | str | Client name — truncated to 25 chars on sticker |
| `jobname` | str | Project name — truncated to 25 chars on sticker |
| `qty` | int | Number of stickers per truss |
| `ply` | int | If `> 1`: total stickers = `qty × ply`; if `== 1`: total = `qty` |

## Job Status Model

### Unified Status (merged app has two status columns per job)

**Sticker Status:**

| Status | Condition |
|---|---|
| `Pending` | CSV + QR exist, but no `Stickers_*.pdf` or `*_Summary.txt` yet |
| `Completed` | Both `Stickers_{job_id}.pdf` AND `{job_id}_Stickers_Summary.txt` exist |
| `Error` | Missing CSV or QR file, or CSV has no data for this job ID |

**Cloud Status:**

| Status | Condition |
|---|---|
| `Uploaded` | Exists both locally and in cloud |
| `Cloud Only` | Exists in cloud but not locally |
| `Local` | CSV + PDF both exist locally, not in cloud |
| `CSV Only` | CSV exists locally, no PDFs |
| `Incomplete` | PDFs exist locally, CSV missing |
| `Pending` | Found in Watch folder, not yet copied/uploaded |
| `Error` | Folder exists but missing required files |

## Sticker Layout

Each sticker page is **100mm × 30mm**:

```
┌────────────────────────────────────────────────────────────┐
│  [Batch ID]      [Customer Name (≤25 chars)]    [QTY/PLY]  │
│                  [Job Name (≤25 chars)]                     │
│                                                             │
│  [Cloud QR]         [TRUSS CODE (large)]      [Token QR]  │
│                                                             │
│  JOBSITE PACKAGE    Builders Inc. — Address   USE ONLY    │
└────────────────────────────────────────────────────────────┘
```

- **Truss code font size**: 48pt (≤4 chars), 42pt (5), 36pt (6), 30pt (7+)
- **Cloud QR**: links to the cloud share URL (from `{job_id}_QR.svg`)
- **Token QR**: encodes `{batch}|{truss_code}|{sticker_type}|{uuid_token}`
- **Sticker type**: `Q01/05` (QTY) or `P01/05` (PLY)

## Cloud Provider Integration

The app supports Dropbox and OneDrive. The active provider is stored in `config.json`
as `"cloud_provider": "dropbox"` or `"cloud_provider": "onedrive"`.

### Dropbox

- Auth: OAuth2 via `DropboxOAuth2FlowNoRedirect` (offline tokens)
- Tokens stored in: `token_dropbox.json`
- Upload root: `/Cloud Manager Uploads/{job_id}/`
- SDK: `dropbox` Python package

### OneDrive

- Auth: OAuth2 via `msal` (Microsoft Authentication Library)
- Tokens stored in: `token_onedrive.json`
- Upload root: `/Cloud Manager Uploads/{job_id}/` (same convention)
- API: Microsoft Graph API via `requests`
- App registration required in Azure portal (Client ID + Client Secret)

### Shared Link Behavior

Both providers must:
1. Upload files to the job subfolder
2. Create a publicly shareable link for that folder
3. Generate a QR code SVG from that link → save as `{job_id}_QR.svg`

## Threading Rules

Tkinter is **not thread-safe**. All UI updates from background threads MUST use
`root.after(0, callback)` — never call widget methods directly from a thread.

```python
# WRONG — crashes randomly
self.tree.item(item, values=(...))

# CORRECT — schedule on main thread
self.root.after(0, lambda: self.tree.item(item, values=(...)))
```

Long operations (scanning, generating, uploading) run in `daemon=True` threads.
Progress updates go through `root.after()`.

## Code Conventions

- **Language**: All comments and UI strings in **English only**
- **No dead code**: Remove unused functions and methods
- **No debug prints**: Use `logging` module, not bare `print(f"DEBUG: ...")`
- **Imports at top**: All imports at module level — no imports inside functions
- **No global variables**: State lives in class instances (`AppConfig`, `TrussyApp`, etc.)
- **Error handling**: Log errors with `logging.exception()`, show user-friendly
  messages via `messagebox`; never silently swallow exceptions with bare `except: pass`
- **Windows paths**: Use `os.path.join()` or `pathlib.Path` — never string concatenation
  with `/` or `\`

## What NOT to Do

- Do not call Tkinter widget methods from background threads directly
- Do not hardcode `APP_KEY`, `APP_SECRET`, or any credentials in source code
- Do not use `os.system()` — use `subprocess.run()` or `os.startfile()`
- Do not import packages inside functions
- Do not define the same function/method twice
- Do not add Spanish comments — English only
- Do not use bare `except: pass` to silence errors silently
- Do not write to `config.json` from multiple threads simultaneously
- Do not assume the `icons/` folder always exists — handle missing icons gracefully
  with a `try/except` that falls back silently (icons are cosmetic)
- Do not modify anything in the `legacy/` folder — it is reference only
